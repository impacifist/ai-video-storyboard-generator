# 장면의 흐름을 우선하는 클립 변환 설계

작성: 2026-10-17

상태: 부분 구현. 로컬 변환기에 문장별 우선 배치, 대사 시작 계기, 인접 클립의 공유 연결 설명, 자동 모드의 클립 내부 시간 배분을 적용했다. 사용자가 지정한 클립 길이·개수는 유지한다. 경계 후보의 의미 기반 최적화와 ComfyUI 문맥·프레임 시간 어댑터는 후속 범위이며, 워크플로우와 실제 영상 생성은 이번 수정에서 변경하지 않는다.

## 목표와 사용자 흐름

15초는 생성 요청의 상한이다. 장면을 끝내거나 다음 구도로 바꾸라는 신호로 사용하지 않는다.
대사·행동·감정의 흐름을 먼저 잡고, 자연스러운 경계에서 생성 구간을 나눈다.

사용자 화면은 **자동 추천 → 필요한 클립의 초만 수정 → 변환**을 유지한다.
문맥 프레임 수, 블렌드 가중치, 경계 상태와 타임코드 정책은 기본 화면에 추가하지 않는다.
각 클립에는 길이와 포함된 컷을 표시하고, 연결 설명은 기존 펼침 영역에서 확인한다.
원본과 예상 완성본의 전체 길이는 함께 보여준다.

## 조사에서 확인한 것과 남은 불확실성

- 현재 로컬 자동 추천은 컷 경계·대사 예상 시간·묶음 길이를 계산한다. 분할 계획과 프롬프트의 시간 배정은 코드로 연결되지만 실제 영상의 움직임은 검사하지 않는다.
- 프롬프트 조립기는 같은 원본 컷을 나눈 경우 공유 상태를 양쪽에 삽입한다. 현재 공유 상태에는 인물의 위치·자세·시선·감정과 소품이 있으며, 움직임의 진행 단계·속도·카메라의 진행 상태·음성 연결은 별도 구조로 보장하지 않는다.
- 사용자가 지정한 기존 3구간 H3 워크플로우의 저장 상태에서는 세 Director가 모두 15초다. 후속 두 구간은 Motion Context의 앞쪽 문맥을 고정하고 Trim 노드로 제거한다. 문맥 설정은 22프레임, 해당 노드의 FPS 설정은 24다.
- 로컬 Motion Context 구현은 문맥을 기존 타임라인의 앞부분에 배치한다. 그만큼의 새 생성 시간을 자동으로 뒤에 추가하는 구현은 아니다. Trim은 같은 길이의 앞쪽 영상과 오디오를 제거한다.
- 따라서 저장 상태의 22/24, 약 0.917초는 후속 구간의 문맥 영역이다. 이를 새 대사·행동에 쓸 수 있는 시간으로 계산하면 안 된다. Director의 VAE 프레임 정렬까지 적용한 실효 길이는 실행 프로필의 실제 프레임 수로 결정해야 한다.
- 워크플로우에 저장된 첫 구간은 14초에 새 컷이 시작해 1초 뒤 생성 경계를 만난다. 다음 구간은 같은 손동작을 이어받도록 쓰여 있다. 두 번째→세 번째 구간에는 실제 컷 전환도 지정되어 있다. 모든 15초 경계의 구도 변화가 의도하지 않은 전환인 것은 아니다.
- 중간 구간에서 끝 프레임을 강제로 정지시키는 지시가 있다는 근거는 확인하지 못했다. 실제 영상·실행 로그·경계 프레임을 대조하기 전까지 정지 패딩, 프롬프트, 문맥 제약 또는 후처리 중 하나를 확정 원인으로 단정하지 않는다.

위 내용은 저장 JSON과 로컬 노드 구현을 읽은 결과다. 과거 영상이 같은 파일·코드·스위치 상태로 실행되었다는 증거는 아니다. 사용자의 원본 워크플로우나 결과 영상은 수정하지 않는다.

## 처리 순서

```mermaid
flowchart LR
    A[승인된 콘티] --> B[대사와 행동의 흐름 파악]
    B --> C[자연스러운 경계 후보]
    C --> D[실효 시간에 맞춘 클립 계획]
    D --> E[인접 구간의 연결 계약]
    E --> F[모델별 프롬프트 조립]
    F --> G[영상 생성과 경계 검토]
```

1. 기존 컷의 목적·행동·대사·카메라·연속성에서 준비, 실행, 반응, 다음 행동으로 넘어가는 단계를 파악한다. 이 단계는 기존 승인 내용을 구조화하는 작업이며 새 사건이나 대사를 쓰는 작업이 아니다.
2. 한 문장이 끝난 지점, 소품 전달이 끝난 지점, 반응을 읽은 지점, 원래 계획한 컷·장면 전환을 경계 후보로 둔다. 대사 중간, 인식→반응의 중간, 큰 동작의 불안정한 순간은 가능한 한 피한다.
3. 생성 상한 안에서 경계의 적합성, 대사 보존, 짧은 꼬리 구간 방지, 불필요한 클립 수를 순서대로 고려한다. 균등한 길이나 15초 채우기를 경계 적합성보다 우선하지 않는다.
4. 컷을 나눠야 한다면 같은 동작의 이어지는 부분으로 취급한다. 카메라 리셋이나 새로운 시작 포즈를 만들지 않는다.
5. 사용자가 클립 초를 바꾸면 원본을 유지한 채 계획을 다시 계산한다. 모든 컷을 같은 비율로 압축하기 전에 대사와 중요한 행동 구간을 보호하고, 조정 가능한 반응·여운의 길이를 먼저 검토한다. 들어가지 않는 내용은 속독 지시로 숨기지 않고 간단한 검토 메모로 알린다.

초기 구현의 숫자 휴리스틱과 AI가 판단한 경계 후보는 구분한다. 경계 판단은 기존 변환 호출에 포함해 추가 유료 호출을 기본으로 만들지 않는다. AI의 제안이 원본 ID·대사·컷 순서를 바꾸면 채택하지 않고 기존 안전한 경계를 유지한다. 확신도만으로 영상의 연속성을 보증하지 않는다.

## 경계 종류별 연결 계약

| 종류 | 앞 클립의 끝 | 다음 클립의 시작 |
|---|---|---|
| 같은 컷의 연속 동작 | 끝 포즈로 정착시키지 않고 진행 중인 행동을 넘긴다 | 같은 구도·시선·동선·동작 단계에서 이어간다. 준비 동작을 반복하지 않는다 |
| 원래 계획한 컷 전환 | 승인된 전환 계기를 보여준다 | 다음 컷의 시점에서 같은 사건의 다음 순간을 보여준다. 구도를 억지로 일치시키지 않는다 |
| 장면 전환 | 원본이 정한 시간·공간 전환을 따른다 | 원본이 정한 새 장소·시간을 설정한다. 롱테이크 연결을 강제하지 않는다 |
| 작품의 마지막 | 원본의 결말·의도된 정지·여운을 허용한다 | 다음 클립을 만들지 않는다 |

인접한 모든 클립에 내부 연결 ID를 부여한다. 같은 컷의 분할 경계만 처리하는 현재 구조를 확장하되 기존 프로젝트 파일은 변경하지 않는다.

내부 연결 정보에는 기존 인물·소품 상태와 함께 다음 내용을 담는다.

- 어떤 행동이 끝났고 무엇이 아직 진행 중인지, 이어받을 동작 단계와 방향·속도의 질적 설명
- 카메라가 고정인지 이동 중인지, 같은 컷이면 유지할 구도·시선축·이동 방향
- 대사가 끝났는지, 다음 화자는 누구인지, 이어지는 환경음·효과음이 무엇인지
- 실제 편집점인지 기술적 생성 경계인지, 원본의 어떤 컷과 근거로 정했는지

같은 연결 계약을 양쪽 프롬프트에 사용한다. 현재 텍스트만으로 실제 카메라 행렬·손의 좌표·오디오 파형을 추정했다고 주장하지 않는다. 후속 구간에 시작 상태를 설명하더라도 인물이나 장소를 처음 소개하는 재연출로 바꾸지 않는다.

## 시간은 두 층으로 관리

시간 정보를 전부 없애지 않는다. **코드의 시간 예산**과 **모델이 읽는 연기 지시**를 분리한다.

코드는 원본의 시간 범위, 생성 요청 길이, 실제 생성 프레임 수, 앞쪽 문맥·제거 프레임 수, 남는 새 영상 길이, 최종 누적 재생 시간을 구분한다.

```text
새로 이어 붙일 프레임 = 실제 생성 프레임 - 앞쪽 중복 제거 프레임 - 별도로 확인된 제거 프레임
새 영상 시간 = 새로 이어 붙일 프레임 / 해당 출력의 FPS
```

후속 프롬프트의 타임코드가 생성 타임라인 기준이면 앞쪽 문맥 영역 이후부터 새 행동을 배정한다. 반대로 새 내용 기준 타임코드를 사용하는 실행 어댑터라면 그 어댑터가 문맥 오프셋을 변환한다. 양쪽에서 오프셋을 더하거나 둘 다 생략하지 않는다.

표준 API용 변환에서는 검증된 문맥 프레임 계약이 없으면 문맥 길이를 0으로 취급한다. 모든 H3·Seedance 실행에 22프레임을 적용하지 않는다. 기존 ComfyUI 방식에는 별도 실행 어댑터가 실제 노드의 프레임 정렬과 제거량을 읽어 시간 예산을 산정해야 한다. 프롬프트만으로 이 실행 계약을 자동 감지할 수 있다고 가정하지 않는다.

이 어댑터는 길이를 맞추려고 생성 상한을 몰래 늘리거나, 대사를 제거하거나, 동작 끝을 임의로 잘라내지 않는다. 사용자에게 보이는 초와 생성 요청, 실제 남는 길이가 다르면 계획·내보내기 메타데이터에 차이를 기록한다. ComfyUI의 실제 FPS·프레임 수가 없으면 실효 길이 검증은 미완료로 둔다.

## 최종 프롬프트 작성 정책

- 매초 할 일을 배치하는 문장 대신 준비→행동→반응→연결을 자연스러운 영어 문장으로 표현한다. 초 단위 정보는 필요한 실제 컷 전환과 모델 가이드의 필수 문법에 사용한다.
- H3의 실제 컷에는 기존 가이드의 `[Shot N] At MM:SS.mmm` 문법을 유지한다. 단순 생성 경계를 새 컷으로 만들지 않는다. 첫 컷 표기와 대사·참조 이미지 문법도 유지한다.
- 같은 컷의 연결 끝에는 장면 종료·정착·페이드·속도 감쇠를 임의로 넣지 않는다. 다음 구간도 재도입·준비 동작 반복 없이 이어간다.
- 새로운 15초 전체를 별도의 작은 이야기로 완결하려 하지 않는다. 마지막 작품 클립과 중간 생성 구간을 구분한다.
- 공간·캐릭터·카메라·환경음의 필요한 연결 조건은 각 프롬프트에 유지한다. 반복되는 설정 설명이 장면을 다시 시작하라는 지시가 되지 않도록 쓴다.
- 원래 의도한 침묵, 유지 샷, 일본 2D 애니메이션의 절제된 연기는 보존한다. 길이를 채우려고 넣는 공백·반복·정지와 구분한다.
- 영어 지시문, 원문 대사·화자 보존, 모델별 참조 번호와 섹션, 실제 가이드 충돌 검증을 유지한다. 불확실한 연출 평가는 새 저장 차단 조건으로 추가하지 않는다.

연속 동작의 연결 문장 예시는 다음과 같다. 특정 작품의 수정본이 아닌 문법 설계 예시다.

```text
Outgoing: Carry the ongoing hand movement through the clip boundary at the same pace and camera view. Do not settle into an ending pose or add a transition.
Incoming: Continue that hand movement from its current phase and direction in the same view. Do not repeat the initial lift or introduce the scene again.
```

## 구현 범위와 순서

1. `clip_planning.py`: 시간 채우기보다 경계 적합성을 우선하도록 자동 계획을 보강한다. 대사·행동 보호 구간과 실제 편집/연속/장면 전환을 기록한다.
2. `conversion.py`: 기존 변환 호출에서 원본을 근거로 연결 계약을 작성하게 하고, 계획·출력·대사를 코드로 대조한다. 같은 연결을 양쪽에 한 번씩 배정한다.
3. `prompt_renderer.py`와 공통 지침: 초별 수행 명령을 완화하고, 모델의 필수 문법과 실제 컷 전환 시각은 유지한다. 중간 클립의 임의 마무리를 방지한다.
4. WebUI: 기존 숫자 입력과 펼침 영역을 유지한다. 기본 화면에 새 모드나 전문 설정을 늘리지 않는다.
5. 별도 ComfyUI 연결 단계: 실행 어댑터의 문맥·프레임 시간 계약을 적용하고 실제 출력과 대조한다. 사용자 원본을 먼저 덮어쓰지 않고 복사본에서 검증한다. 이 설계 문서 작성은 워크플로우 변경이나 영상 재생성을 실행하는 단계가 아니다.

## 완료 검증

| 항목 | 자동 검사 | 실제 영상 검토 |
|---|---|---|
| 원본 보존 | 문서 불변, 컷 ID·순서·화자·대사 정확히 한 번 | 의도한 사건과 반응이 남아 있는지 |
| 같은 컷 연결 | 연결 ID와 양쪽 상태·동작·카메라 지시의 일치 | 경계 전후 손·몸·시선·카메라 속도가 이어지는지 |
| 실제 컷 전환 | 원래 편집점에만 전환 문법 존재 | 의도한 편집인지 부자연스러운 튐인지 |
| 시간 | 모델 상한, 구간 배정, 문맥 제거, 누적 프레임 계산 | 대사 누락·속독·공백·동작 반복이 생기는지 |
| 오디오 | 원문 중복 없음, 제거량과 FPS 계약 확인 | 음절 잘림, 환경음 단절, 음성·입 모양 어긋남 |
| 사용자 조작 | 자동 추천·초 수정·변환, 기존 저장본 호환 | 추가 전문 설정 없이 의도대로 조정 가능한지 |

동일한 콘티·모델·참조·워크플로우 조건에서 기존 방식과 비교한다. 경계 전후 약 1~2초를 정상 속도·느린 재생으로 확인한다. 실제 클립 수·길이·문맥 프레임·샘플링 조건과 비교한 결과를 기록한다. 모의 AI나 형식 테스트 통과를 실제 영상의 연속성 개선으로 보고하지 않는다.
